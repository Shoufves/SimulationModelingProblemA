# 地区新能源双向差价结算：独立账本

2026-10-20。新增 `src/energy_model/q2_cfd.py` 与 `tests/test_q2_cfd.py`，只实现可独立调用的机制差额计提、双方应收应付与有限现金支付。**尚未接入 `q2_national.py`、`q2_revenue.py`、全国前瞻或投资预期**；未重写历史结果、源码清单或已有实验哈希。接口通过不能解释为全国政策覆盖、项目实际收入或科学验收。

## 已核读证据与没有推定的参数

- 国家136号原件：`data/raw/q2_revenue/ndrc_renewable_market_2025.html`，第三部分（四）至（九）。市场均价低于机制价补差、高于机制价反向结算；机制量、价、期限由地方明确，费用归当地系统运行费用；按月结算和分解，实际电量不足时据实结算并年内滚动清算。机制电量不重复获得绿证收益，初期不另开展其他形式差价结算；原财政补贴按原有规定执行，不能把两类账混合。
- 上海原件：`data/raw/q2_cfd/shanghai_2025_results.html`，沪发改价管〔2025〕45号，（一）及（二）。入选2039个项目、约5.4亿千瓦时、机制价0.4155元/kWh含税；已投产项目2026-01-01开始，未投产项目原则上申报投产日次月1日起。完整附件 `shanghai_2025_awards.xlsx` 的H/I/J/F列分别为机制电量、机制电价、执行期限与**（承诺）投产时间**。核读摘录见 `q2_cfd_evidence.md`，来源哈希见原有 `data/raw/q2_cfd/source_manifest.json`。

代码没有装入上述地区价格、名单、12年期限、额度或全国参数；既没有把承诺日期当实际投产，也没有把地方样本加权外推全国。地方月分解、滚动清算细则、具体市场均价、负价适用及合同证明须由调用者提供。仅凭这里核读的两份通知，不能断言全国允许负参考价、采用零价下限或所有项目自动适用同一合同。

## 接口

`PriceBasis(currency, tax_basis, vat_rate, energy_basis)`：

- 价格统一为 `nominal_CNY_per_MWh`；kWh转MWh需显式乘1000后传入。
- `tax_basis` 为 `vat_inclusive` 或 `vat_exclusive`，并传税率小数；参考价与机制价必须完全一致。模块不自动换税或平减，也不模拟增值税实缴。
- 最小实现只支持 `actual_net_export`，毛发电量、自用电或零售电价不能替代实际净上网计量。

`CfdContract(...)` 显式登记项目、生产商、地区、风/光技术、资格布尔及证据、核实的实际投产日期及证据、机制起始日和结束日、机制价与价格口径、市场参考价方法、负价规则及依据、日历年度额度和逐月额度。缺失年度/月度分解不自动按十二等分，也不填无限额度。额度输入复制并冻结，调用方后来修改原字典不改变合同。

实际投产未知时允许登记 `actual_commissioning_date=None`，但不能产生任何期间新结算。核实后，调用者应构建带实际日期的合同；本轮不实现待建项目登记更新或自动政策资格认定。机制期起始仍须按适用地区合同显式给出；不能仅以实际投产日推导其当然开始。结束日采用**不包含该日**的半开区间，无默认永久续期。

`MeteredPeriod(...)` 提交项目及地区、实际计量起止日期、实际净上网量、其中合格净上网量、申领机制量、计量依据、同月同类项目参考价及方法、价格口径、申领量上对应的绿证收入及其他差价结算额。最后两个值必须明确传入，非零时拒绝在同一申领量上叠加。

一个计量区间必须在同一个日历月内，并完整处于已实际投产且机制有效的日期范围；月初、月底或期中跨生效/失效日时，须拆分真实计量。模块不把整月电量按天数猜测摊分。`0 ≤ 申领量 ≤ 合格量 ≤ 实际净上网量`，且申领量受月及年额度限制。超过时明确拒绝，不能按额度制造实际发电，也不静默截断数据错误。

`quote_settlement(contract, meter)` 为纯函数：

`生产商有符号应计差额 = (机制价 − 市场参考价) × 合格申领机制电量`

正数产生“系统应付/生产商应收”，负数产生“生产商应付/系统应收”。`negative_market_price_rule` 必须显式为 `reject_negative` 或 `allow_signed`，并给依据；后一种按带符号参考价原值计算，不设未经授权的零价下限。纯报价只验证单笔，不保留累计量；正式连续调用必须经账本计提。

`CfdLedger(region, opening_date, contracts, opening_system_cash_cny, opening_producer_cash_cny, opening_obligations, opening_year_used_mwh, opening_month_used_mwh)` 为独立账本：

开账时**必须**逐项目提供开账所在日历年、日历月的累计已用机制电量，两个映射均以项目编号为键，精确覆盖所有合同；即使新机制尚未开始或已使用量确为0，也须明确写0，未知不能默认0。历史应收应付金额与已计量机制电量是独立状态，不能用欠款金额反推电量。

开账累计量须非负、有限、月量不高于年量，且不超对应的合同年/月额度；年量不能超过开账前各月的有效额度之和加本月明确已用量。月初没有本月已过去计量区间时，本月已用必须为0；同理1月年量与月量必须相等。尚未实际投产或尚未机制生效之前不能导入已用量。中途开账因此只保留年/月剩余额度，不会重新发一遍全年额度。已失效项目的历史合法欠款仍可导入清偿，当前年/月相关使用量仍需显式说明；不相关的历史年度无需凭空重建，因为新计量不得早于开账。

1. `accrue(meter, posting_date=...)` 完整计提差价义务，返回 `obligation_id`；付款方缺钱也不减少应计额。记账日期不得早于最终计量结束日，所有账本操作日期单调不减；不允许账本开账之前的计量进入本期。
2. 在开账累计量基础上累计每项目月/年申领量；拒绝同一项目重复或重叠的计量区间、未知项目、超累计额度和无实际投产资格的计提。无自动月间结转、期限展期、额度修订或历史冲销。年度额度逐年提供；既有应付款不会因年末、合同到期或未来零额度清除。
3. `pay(obligation_id, requested_cny=..., on=...)` 对指定义务付款；请求不得超过尚欠额，实际支付受付款方现有现金限制。收到500元只能付500元，余款继续挂账。正向付款和反向付款具有相反且等额的系统/生产商现金变化，无自动抵销，也不假设政府无限补足。
4. `add_cash(party=..., amount_cny=..., on=..., evidence=...)` 录入明确的真实外部现金。`party="system"` 表示系统结算账户；其他名称必须是已登记的生产商。其来源依据由调用者保存，不把机制入选额度或新发票当成现金。调用顺序及支付优先序由调用者明确指定，本模块不声称模拟地方清算优先政策。
5. `OpeningObligation(...)` 可导入经过核对的历史正、反向应付；需要已知项目、独立编号、历史日期及证据。开账日后到期或失效不阻止清偿此前合法欠款。
6. `balances()` 同时输出系统现金/应收/应付与各生产商现金/应收/应付；双方应收应付逐笔对应。现金总额等于开账现金加明确外部注资，内部分付不能创造或销毁现金。`volume_usage` 输出包含开账量的年/月累计使用记录；`obligations`、`settlements`、`payments`、`cash_events` 返回独立的审计记录副本。

金额与电量采用 `Decimal`（默认28位有效数字），拒绝非有限值、布尔伪数值和负的现金/电量输入；负参考价及有符号差额除外。这里没有擅定按分舍入、税款结转或通胀换算规则。实际接入须另按适用清算规范确定货币舍入及真实税务处理。

## 财务边界与接入缺口

账本标签为 `regional_system_operating_cost_cfd_not_fiscal_subsidy`，财政补贴计提恒为0。这仅表明本账没有新增财政补贴，并不代表项目不存在独立的旧补贴权利。市场电费、原财政补贴、机制差价、绿证必须保持各自账本与可兼容边界；不能把已经包含差额的总电价再加一次本账差额。

本轮不自动计算市场电费，不计算投资NPV、不改变发电或弃电、不延长补贴资格、不自动认定项目投产。`eligible_net_export_mwh` 及绿证/其他差价声明是调用方提供的经核验边界；模块不能替代全国电网计量或跨系统重复申报核查。跨月滚动清算、事后计量更正、撤回、额度重分解、市场参考价不同周期、批量分配及全国财务接线均未实现；当前全国前瞻仍未使用本接口。
