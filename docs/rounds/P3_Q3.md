## 2. 成员先保存工作，再同步已有仓库

无需重新 clone。每人在自己的已有 clone/worktree 的**仓库根目录**操作，目录名和磁盘位置可以不同。

先检查：

```powershell
git rev-parse --show-toplevel

```

有未提交工作时，先在自己的旧工作分支做本地备份提交，或使用下面的临时保存方式；确认保存成功后再切换分支：

```powershell

git stash list
git status -sb
```

`stash -u` 不包含被 `.gitignore` 忽略的文件；其中有价值的原始材料、实验结果应另行保存。不要用清理、重置或覆盖文件来“同步”。不要把旧任务的 stash 直接恢复到 main 或 P3 分支；需要继续旧任务时回到原工作分支处理。

保存完成后，更新 main：

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git rev-parse HEAD
```

## 5. 六组情景与时间连接

| 情景 | 相对 S0 只改变什么 | 必须检查 |
|---|---|---|
| S0 | 交接模型的既有政策、需求与技术趋势 | 重跑/核对基准；不强制达峰或中和；模型有修订时给修订前后差异 |
| SP | 碳价路径及明示生效时间 | 保留适用覆盖、配额和真实结算；其他政策若变动另开子情景 |
| SG | 指定来源/通道的进口天然气可交付能力及恢复 | 国内生产不一并缩减；其他来源、库存与提取分别受限；不把来源集中度直接当中断损失 |
| ST | 新储能项目的功率/能量投资成本 | 不顺带提高效率、寿命或现有容量；降本须经申请、融资、工期才能变成设备 |
| SW | 同期风、光可用率及水电可发能量上限 | 来源事件或条件假设身份清楚；首轮不顺带增加高温需求 |
| SGW | 原样叠加 SG 与 SW | 事件日历、幅度和事前状态与单项配对相同，不另加第三种冲击 |

SP/ST 比较长期路径；S0/SG/SW/SGW 先复制同一事前资产、库存、设备和服务状态做连续短期配对。短期事件的持续、恢复和 SOC 按真实连续时段计算，不能用循环代表日或年度权重伪造事件时长、恢复或季节储能。

独立压力测试与带明确事件日历的年度反馈实验分开。只有明确将事件嵌入某年时，才把其实际损失、库存及资金变化接入后续年度；不重复计入日常收益，不预设每年必然发生灾害。无概率资料时只报告条件事件损失，不报全年可靠性概率。

现阶段可在已说明的全国聚合范围先完成条件实验。若扩展地区、线路或技术，需要相应输入和守恒检查；单节点结果不能解释为跨省拥塞或具体地区安全结论。

## 6. 安全框架、H01/H02 与政策筛选

**安全框架。** 按实际模型区域和服务分别报告未满足量/比例、最长连续缺供、恢复时间、库存最低值、进口暴露、资源费用、公共预算、累计排放及关键服务约束；原单位先分报，再用冻结需求归一化。零需求、未恢复、窗口末端截断及不可行状态须有定义。不能把不同服务的物理量直接相加，也不能用平均改善掩盖关键服务受损。

**H01：转型速度与配套滞后。**

- 分开设备替代速度 `vE`、合法退出速度 `vR` 和配套额外延迟 `L`，分别做 `vR×L` 与 `vE×L`，公开全部点的成本、累计排放、缺供和可行性。
- 提前规则只用当时可知资产、队列、资金及预先登记压力条件预测缺口；预测窗口与触发阈值先冻结，来不及建设的项目不能立即补缺。
- 与固定日程、费用排序、“替代服务可用后再退出”的透明保供规则比较。共用信息、可用动作和实施约束；固定项目时序实验与完整主体响应实验分报。
- 计入保留/延寿费用、额外排放和期末资产，不靠无限延后到 2060 年之后规避转型；选择条件与检验条件分开。

**H02：气源与天气联合压力。**

- 在四组配对下，对同一服务/单位/窗口的缺供指标计算 `J = U(SGW) − U(SG) − U(SW) + U(S0)`。
- 保存各来源供气、发电/工业等用途竞争、转换、库存/SOC、设备动作和服务缺口的连续过程，网络未建模时明确无跨区解释。
- 冻结指定的事件后替代响应，共用原资源、需求及事前状态，对比 `J正常 − J冻结`；不能以无限供气、降低需求、重置库存来“关闭耦合”。
- `J≠0` 只能说明联合增量差异，机制归因另需冻结对照及过程证据；短期传播与后续投资适应分报。无显著增量或创新无效也是有效结果。

**政策优化。**

围绕能源结构、多能调度、储备应急、市场机制、科技应用五个角度，建立“已观察瓶颈 → 候选动作 → 谁支付/谁执行 → 预算/工期/许可 → 运行效果 → 失效条件”的证据链。五方面建议均需回应；无数据支持的动作写清限制，不伪造量化效果。

先比较有解释的单项及必要两项组合，再做有限政策组合筛选。诊断性小幅增容可定位瓶颈，正式方案必须经过主体申请、审批、付款与建设，需求响应须守恒或计入服务损失。研发突破属于外部条件；没有投入到技术效果的证据，不把免费降本作为可任意选择的政府动作。

政策在相同信息、初态、外部条件、服务、成本价年和碳边界下比较。对事先指定条件集检查预算、资金承诺、工程可行性、累计排放及关键服务界，报告成本—排放—安全非支配取舍与最坏表现；无现实概率不称期望最优，无充分搜索不称全局最优。无可行方案须报告冲突，不静默放宽条件。筛选集与扩展/独立检验集分开，公开排序翻转及假设敏感性。
