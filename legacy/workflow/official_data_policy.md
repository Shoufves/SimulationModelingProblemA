# 官方数据准入规范

本规范落实用户“网上收集的数据必须以有说服力的官方数据为准”的要求，是研究工作规则，不是要求用户逐项批准。

## 来源适用范围

| 数据 | 首选原始发布主体 | 使用边界 |
| --- | --- | --- |
| 全国能源、GDP、能源平衡 | 国家统计局及正式统计年鉴/公报 | 同版修订、口径及脚注优先于方便获取 |
| 装机、发电、储能、建设 | 国家能源局、国家统计局发布资料 | 协会数据只有被官方表明确采纳时按该官方表使用 |
| 油气煤进出口 | 海关总署及官方统计资料 | 商品编码、数量单位、净/毛进口、贸易/平衡口径一致 |
| CO2因子、清单、碳市场 | 生态环境部及主管部门公开文件 | 明确适用行业、燃料、CO2/CO2e、年份及覆盖范围 |
| 政策、价格机制、技术规范 | 国务院、发改委、能源局及主管部门 | 政策目标不是已实现结果，指导价不是市场成交均价 |
| 地方能源与需求 | 省级统计局和能源主管部门 | 只能支持对应行政范围；汇总前核对口径和缺省地区 |
| 气象、水文及资源 | 气象、水利、自然资源等主管部门 | 时空分辨率、测站与代表性必须说明 |
| 国际技术/核算方法 | IPCC、IEA、IRENA等政府间机构正式出版物 | 适用性审查后用于方法或参数背景，不能冒充中国观测 |

以上是检索路线，不表示已经获得对应文件。国企官方资料可说明该企业或项目，不能由一个企业外推全国；行业协会和科研论文可帮助定位官方依据，正式事实表不以其二手转述替代原始官方统计。

## 每个数据集的证据链

必须保留发布机构、正式文件名、网址、年份、原表/页/段定位、原单位、统计范围、发布/修订状态、访问时间、读取方法、使用范围，以及可复核的原件或官方页面留存。仅有来源域名不够。

下载失败可采用完整官方页面或原表截图留存，附网址与时间，并覆盖使用数值及相关脚注；不得把搜索摘要写成原表快照。原始数据和处理后数据分层，保留哈希与转换关系。关键输入要独立重读原表；存在第二个适用官方版本时比较，不为凑“双来源”重复引用同一报告的转载。

官方PDF可按页面读取并视觉核对，将实际使用段落、数值及相关脚注留存为明确标注的页面摘录。登记official_page_capture时必须说明是PDF页文本、是否下载原件、截图是否本地归档；摘录不能称为完整PDF或原始二进制。官方发布的编委会/行业报告须同时记录编制、指导、发布身份及基础数据来源；只有被正式公开文件明确采用且适用的字段进入限定用途子集，不能把官方托管等同于全部数字由部门自采。

2026-10-17补充：官方年鉴图片在工具中可以完整显示、但本地下载和浏览器截图通道失败时，允许与PDF一致的明确标注文字摘录方式。必须直接查看原图，另次重开核对所选全部数值、年份、列名、单位及相关注释，并留存读取路线、官方原图URL、表号/行/列、所选数值的文字摘录及适用的官方章节说明。记录原图二进制和截图均未本地归档，离线视觉复核能力受限。不得把已有候选表复制后自称原图读取；未读清的数值或影响口径的注释保持候选。限定用途审查只覆盖明确摘录的字段，不批准原候选整表。

官方原始来源的直接复读及适用范围核验是必须条件；第二独立来源不作统一前置条件。有适用第二版本时须比较，不能用同一发布的转载凑独立来源。此补充统一图片和PDF的文本留存标准，不降低官方来源和逐值复核要求。

## 状态

1. candidate：只有线索、摘要或未核对转录，供探索和检索，不进入正式模型。
2. reviewed：官方原文/原表与相关脚注已核对，证据归档、逐值检查、单位年份及修订关系检查完成。
3. approved_input：从reviewed中选择实际需要的数据，写入正式输入清单。
4. rejected_or_superseded：来源不合格、口径不适用或被明确新版替代，保留原因与历史记录。

“已核验”由执行者完成真实核对后登记，不需要默认再向用户要许可。脚本只能检查登记、文件与哈希等条件，不能代替对原文内容的理解。

## 含糊数据的处理

- 摘要和页面正文冲突：保留候选，核对正式原文、脚注和版本。
- 官方来源之间不同：同时登记；解释范围、时间、修订、四舍五入或统计调整；不能择取更有利于结论的数据。
- 同版数据不足：优先找可比官方序列；确需跨版则建立桥接说明并标记断点，未解决前不连续校准。
- 缺失：保留null与影响说明；不能编造、把0当缺失或把插值当观测。
- 电力、氢、抽蓄：转换和储存单列，避免一次能源重复计算。
- 技术成本/未来政策没有官方确定值：作为明确的研究假设或待校准参数，注明官方依据、推断过程、范围及敏感性；不能归入历史事实。
- 论文中的方法创新可引用学术研究；其中的数字只有回溯到官方原始证据并核验后才能进入本项目正式数据。

## 登记格式

data/evidence_reviews.json中的一条review需包含：
review_id、dataset_path、dataset_sha256、source_registry_sha256、status=reviewed、reviewer、checked_on、original_values_checked、units_period_scope_checked、revision_compatibility_checked、evidence_files。

每个evidence_file包含source_id、path、sha256、official_url、capture_kind、locator、captured_on、scope_and_units、revision_note、extraction_method。captured_on和checked_on使用YYYY-MM-DD；留存日不能晚于核验日，核验日不能在未来。locator必须定位实际使用的表/页/段及脚注；scope_and_units说明年份、统计范围和单位。capture_kind可为official_original或official_page_capture；不接受search_snippet。网址必须与来源登记一致，来源登记需有publisher和title。
每个实际使用的source_id均须有证据。复核必须针对登记数据集的全部数值；只核对部分时先输出可追溯的子集，再登记该子集。

审查可附source_records_sha256，按source_id固定实际使用来源记录的规范JSON哈希（ensure_ascii=False、sort_keys=True、separators=(',', ':')、UTF-8）。提供该字段时，键必须恰好覆盖所用来源，逐项校验替代整目录哈希比对；原source_registry_sha256仍作为审查时全局版本留档。未提供时继续执行整目录检查，兼容既有审查。这样新增无关来源无需重做该子集审查，引用来源的任何字段改变仍会使审查失效。数据与证据文件哈希要求不变。

workflow/model_inputs.json记录inputs，每项为dataset_path、review_id、purpose。workflow/source_domains.json本轮仅预置允许主管部门域名；新增地方官方机构需先确认身份、记录规则再纳入，不能用模糊字符串匹配绕过检查。所有文件路径为工作区内相对路径，哈希为文件真实SHA256；数据集或来源登记变化后必须重新确认核验记录。

模块入口可仅检查自身明确声明的数据集；全局证据审计仍检查全部正式清单。模块所需输入缺失、重复、篡改或来源不符必须拒算，不因无关模块审查失效而误判该模块输入无效。方案更换版本需显式更新配置并留下审查记录，禁止静默替换。

情景参数另列scenario_assumptions，至少包括名称、值/单位、适用年份、官方依据或研究假设标签、生成方法及敏感性范围。正式输入完整性检查不等于模型已获历史验证。

当前自动检查器面向data/observations同类JSON观测子集，读取source_id、source_ids、default_source_id及row_sources；不自动审查未来假设、附件清洗表或国际方法参数。附件原件由provided_inputs.json固定，实际使用由W1验收；情景假设与方法参数由W4—W6另行审查。需要新的输入格式时先补充解析和检查，不得绕过来源要求。
