## 1. 必须修复的问题

### [P2] 将到龄退出从“提前退役”统计中剔除

**位置：** `src/energy_model/q3_transition.py:83—88`，指标出口为同文件第234行和第272行。

`mature()` 对所有满足 `q3_exit <= self.year` 的机组，均执行 `retired_early_mw += capacity_mw`，并记录 `action='early_retired'`。但延期规则允许 `q3_exit` 最终等于机组的自然退出年 `exit_year`。这种情况下实际发生的是到龄退出，不能仍计作提前退役。

**实际反例（没有改参数或制造额外冲击）：** 使用已登记的完整主体条件 `vR=0.02、vE=0.25、L=0、cost_order`，运行至2029年：

| 项目 | 实际结果 |
|---|---:|
| 模型报告的累计提前退役 | 19,142.755207 MW |
| 严格早于自然退出年的实际退出 | 0 MW |
| 被误计的机组批次 | `initial/coal/20` |
| 实际退出年 / 自然退出年 | 2029 / 2029 |

该批次在2027年收到退出请求，之后延期至2029年自然到龄。其物理退出年份没有越界，错误发生在事件分类和累计指标。

对独立复跑生成的全部年度账本扫描后，**160个 H01 案例中有98个存在同类误计**。例如同一条件的完整年度结果将452,067.314325 MW计作提前退役，其中201,239.299600 MW实际是在自然退出年退出。这不是只在人为构造输入下出现的边缘问题。

**影响：** `retired_early_mw`、逐年 `q3_early_retired_mw` 及退役事件分类失真，影响对不同规则实际退出节奏的解释，不满足 C4 中结果可核算的要求。该累计计数没有被用来驱动投资、调度或政策排名；目前没有证据表明这项错误改变了能源平衡、资源成本、H02交互或 `policy_2` 的选择，不能夸大为整个仿真失效。

**建议修复：** 以 `实际退出年 < 自然退出年` 判定提前退役；等于自然退出年的单列为到龄退出，或另设“受计划管理的退出”指标，并保留真正的提前退役量。自然寿命、真实退出和资金约束保持。补充“延期后恰好到龄”与“确实提前退出”两个反例，同时让独立验收脚本由退出年份重算指标，不能只检查“不超过自然寿命”。

**修复后需提供：** 正确分类的逐年/累计退役指标、相关H01表和账本，新增反例测试、独立重算记录及新的完整SHA。若仅修正统计，应核对物理路径、成本和政策选择保持一致；若调整了行为规则，再重跑受影响实验。

**证据：** `evidence/retirement_runtime_probe.json`、`evidence/retirement_metric_probe.json`。两份探针源代码一并附上；将其放入该提交的 `tmp/` 目录，用已安装依赖的Python执行。`review_runtime_probe.py` 在当前提交会按预期断言失败，显示提前退役应为0；这与仓库315项原测试通过并不矛盾。
